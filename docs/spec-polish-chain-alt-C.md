## ۱. مسئلهٔ فعلی (Current UI)

```
[✨ زنجیرهٔ پالیش فارسی (Groq/OpenRouter)] [پالیش نهایی روشن ☑]
[همه روشن] [همه خاموش]  hint: هر مدل را با سوییچ خاموش/روشن ...
┌─────────────────────────────────────────────┐
│ ⋮⋮  ①  qwen/qwen3.6-27b   groq   [روشن☑]  ✓ کلید  [▲][▼][✕] │
│ ⋮⋮  ②  openai/gpt-oss-20b openrouter [روشن☑] ⚠ بی‌کلید [▲][▼][✕] │
│ ⋮⋮  ③  allam-2-7b         groq   [خاموش☐] ✓ کلید  [▲][▼][✕] │
└─────────────────────────────────────────────┘
[select مدل ▾] [select provider ▾] [➕ افزودن مدل]
hint: «رابطه کاربری» → ...
[بازنشانی پالیش]
```

**دردها:**
1. **Add گیج‌کننده:** دو `select` هم‌عرض — کاربر نمی‌فهمد `provider` جدا از `model` است؛ خطای تکراری (`قبلاً هست`) زیاد.
2. **اسکن سخت:** ۳ ردیف فشرده، بج `groq/openrouter` ریز و بی‌رنگ، تشخیص مرزبندی ارائه‌دهنده در یک نگاه ممکن نیست.
3. **مسترکنترل مبهم:** «همه روشن/خاموش» روی کل لیست عمل می‌کند؛ کاربر می‌خواهد فقط Groq را خاموش کند (سهمیه تمام شده) بدون دست‌زدن به OpenRouter.
4. **No catalog:** مدل‌های قابل افزودن مخفی در `select` یا پشت «لیست مدل‌ها»ی Groq/OpenRouter — کشف‌پذیری صفر.

## ۲. هدف Alternative C

> **تفکیکِ «کاتالوگِ ارائه‌دهنده» از «ترتیبِ نهاییِ فالبک»**
> - بالا: **تب‌های ارائه‌دهنده** — هر تب کاتالوگ همان provider
> - پایین: **پیش‌نمایش زنجیره (Chain Preview)** — ترتیب نهاییِ میان‌ارائه‌دهنده‌ای، تنها جایِ درگ/ترتیب

اصل هم‌نگار: *ویترین نازک، ماژول عمیق* — `storage.js` همان `POLISH_DEFAULTS: {id, provider, enabled}` می‌ماند؛ فقط View لایه عوض می‌شود.

## ۵. تعامل‌ها (How to ...)

### ۵.۱ افزودن (How to add)

1. تب provider را انتخاب کن (کلیک یا `ArrowLeft/Right` در tablist).
2. در پنل، ردیف مدل → دکمهٔ `＋ افزودن به زنجیره` (فارسی: `＋ افزودن`).
3. اگر مدل قبلاً در زنجیره است: دکمه به `✓ در زنجیره` (disabled, `aria-disabled=true`) تبدیل می‌شود + تولتیپ `قبلاً افزوده شده — در پیش‌نمایش پایین ببین`.
4. افزودن همیشه به **انتهای** `polishChainState` می‌رود (`push`) و پیش‌نمایش اسکرول به انتها + `Logger.toast('افزوده شد: qwen/... (Groq) — جایگاه ۴')`.
5. افزودن سفارشی (مدل خارج کاتالوگ): لینک کوچک `＋ مدل دلخواه…` در انتهای هر پنل → `prompt` یا `input` اینلاین `model-id` + اعتبارسنجی `/^[a-z0-9\/\-\.:]+$/i` → `provider = currentTab`.

> **چرا نه درگ از کاتالوگ به زنجیره؟** درگِ بین دو لیست روی موبایل و با صفحه‌خوان بسیار شکننده است. دکمهٔ صریح + فیدبک توست قابل اتکاتر است. درگ فقط داخل پیش‌نمایش (جایی که ترتیب مهم است) مجاز است.

### ۵.۲ دیدن ترتیب نهایی (How to see final order)

- **تنها منبع حقیقت:** بخش `پیش‌نمایش زنجیره — ترتیب فالبک نهایی` در پایین.
- هر آیتم: `⋮⋮  شماره  نقطه‌رنگی  نام‌مدل  بج‌provider  سوییچ روشن/خاموش  ▲▼✕`
- نقطه‌رنگی + بج هر دو provider را می‌رسانند (رنگ به تنهایی کافی نیست — a11y).
- اگر زنجیره >4 آیتم: پیش‌نمایش `max-height: 220px; overflow:auto` + سایهٔ `scroll-shadow` در لبه‌ها.
- `aria-live="polite"` روی کانتینر پیش‌نمایش: هر افزودن/حذف/جابه‌جایی `ترتیب جدید: ۱ qwen... (Groq)، ۲ gpt-oss... (OpenRouter)` را به صفحه‌خوان می‌گوید.

### ۵.۳ درگ و جابه‌جایی (How to handle drag)

| روش | رفتار |
|-----|-------|
| **درگ موس/تاچ** | فقط در پیش‌نمایش. `draggable=true` روی `.chain-item`، هندل `⋮⋮` با `cursor:grab`. `dragover` → خط راهنمای آبی بین آیتم‌ها. `drop` → `splice` + `persistChains()` + `renderAllChains()` (همان منطق `app.js:217-230` ولی محدود به `polish-preview` container). کاتالوگ اصلاً `draggable` نیست. |
| **کیبورد ▲▼** | دکمه‌های `▲ بالا` / `▼ پایین` روی هر آیتم زنجیره (مثل فعلی `data-up/data-down`). `Enter` روی هندل → حالت جابه‌جایی کیبورد: `Alt+ArrowUp/Down` آیتم را جابه‌جا می‌کند (الگوی `aria-dnd` ساده). |
| **صفحه‌خوان** | هر آیتم `role=listitem` + `aria-label="جایگاه ۲ از ۴: qwen… Groq، روشن"` + دکمه‌های ▲▼ با `aria-label="جابه‌جایی به بالا"` |
| **کاهش حرکت** | `@media (prefers-reduced-motion: reduce)` درگ انیمیشن ندارد؛ جابه‌جایی فوری است (`css/app.css:182`). |

**غیرفعال:** درگ از کاتالوگ به زنجیره، درگ بین تب‌ها، مرتب‌سازی خودکار بر اساس provider.

### ۵.۴ مسترکنترل‌ها (Master controls per tab)

- هر پنل دو دکمه: `همهٔ Groq روشن` / `همهٔ Groq خاموش` — فقط روی مدل‌های **همان provider که در زنجیره هستند** عمل می‌کند (نه کل کاتالوگ).
- لیبل پویا: `همهٔ ${providerLabel} روشن` — مثلاً `همهٔ Groq روشن`.
- رفتار: `polishChainState.filter(e=>e.provider===tab).forEach(e=>e.enabled=true)` → `persistChains()` → توست `همهٔ Groq روشن شد (۲ مدل)`.
- اگر تب هیچ مدلی در زنجیره ندارد: دکمه‌ها `disabled` + تولتیپ `مدلی از این ارائه‌دهنده در زنجیره نیست`.
- حذف کلی per-provider (اختیاری V2): `حذف همهٔ Groq از زنجیره` با `confirm` قرمز — فعلاً خارج اسکوپ.

### ۵.۵ سوییچ روشن/خاموش (Enable toggle)

- دو جا دیده می‌شود (همگام):
  - در کاتالوگ: سوییچ فقط اگر مدل در زنجیره باشد فعال است؛ ورنه `—` یا `disabled` (چون خاموش/روشن بودنِ مدلی خارج زنجیره بی‌معناست).
  - در پیش‌نمایش: سوییچ اصلی — تغییرش فوراً `enabled` را در state عوض می‌کند و کاتالوگ همان ردیف را هم به‌روز می‌کند (دوطرفه bind).
- سوییچ خاموش → آیتم زنجیره `opacity:.45` + کلاس `polish-off` (همان `css/app.css:140`) + از فالبک **رد می‌شود** (منطق `transcription.js` از قبل `enabled!==false` را چک می‌کند).

## ۷. دسترسی‌پذیری (a11y) — WCAG 2.2 AA

| اصل | پیاده‌سازی |
|-----|------------|
| **ساختار تب** | `role=tablist` روی نوار تب، هر تب `role=tab` با `aria-selected`, `aria-controls`, `tabindex` roving. پنل `role=tabpanel` با `aria-labelledby`. کیبورد: `ArrowLeft/Right` (در RTL معکوس)، `Home/End`, `Enter/Space` فعال‌سازی. |
| **نام‌گذاری** | هر دکمهٔ `＋ افزودن` → `aria-label="افزودن qwen/qwen3.6-27b (Groq) به زنجیره"`؛ هر `✕` → `aria-label="حذف …"` |
| **زنده‌خوانی** | پیش‌نمایش `aria-live="polite" aria-atomic="false"` — فقط تغییرات ترتیب خوانده شود، نه کل لیست. |
| **کنتراست** | نقطهٔ provider به تنهایی معنادار نیست — همیشه بج متنی هم هست (۱.۴.۱ Use of Color). کنتراست نقطه روی `var(--surface2)` ≥ ۳:۱. |
| **فوکوس** | `outline: 2px solid var(--accent); outline-offset:2px` روی تب فعال، دکمه افزودن، هندل درگ. ترتیب فوکوس: tabs → catalog rows → preview list. |
| **هدف لمسی** | هر دکمه ≥ ۴۴×۴۴px (۲.۵.۸ Target Size). هندل `⋮⋮` حداقل ۲۸×۴۴ با `padding`. |
| **کاهش حرکت** | `prefers-reduced-motion` → بدون انیمیشن درگ/پالس (`css/app.css:182`). |
| **خطا** | اگر افزودن تکراری → `aria-describedby` روی دکمه + `role=status` توست `قبلاً افزوده شده`. |

## ۸. مزایا / معایب (Pros / Cons)

### Pros

| مزیت | توضیح |
|------|-------|
| **کشف‌پذیری +** | کاتالوگ هر provider جدا — کاربر می‌فهمد Groq چه مدل‌هایی دارد بدون باز کردن `select` طولانی |
| **مرزبندی ذهنی** | تب = provider mental model — مطابق تنظیمات کلیدها در بالای مودال (Groq / Gemini / OpenRouter) — یکپارچگی |
| **مسترکنترل دقیق** | «همهٔ Groq خاموش» وقتی سهمیه Groq تمام شده، OpenRouter دست‌نخورده می‌ماند — درد اصلی حل می‌شود |
| **ترتیب شفاف** | پیش‌نمایش همیشه زیر چشم است؛ حتی وقتی تب Groq باز است، کاربر می‌بیند جایگاه OpenRouter کجاست (برخلاف لیست واحد که providerها قاطی‌اند) |
| **افزودن بی‌ابهام** | یک دکمه `＋ افزودن` کنار هر مدل — نیازی به انتخاب provider جدا نیست؛ خطای provider/model mismatch حذف می‌شود |
| **مقیاس‌پذیری** | افزودن Gemini به‌عنوان تب چهارم بدون شلوغیِ لیست واحد؛ کاتالوگ هر تب می‌تواند `search/filter` بخورد |
| **a11y تمیز** | الگوی تب استاندارد WAI-ARIA — صفحه‌خوان‌ها آن را بهتر از `select` دوگانه می‌فهمند |

### Cons / ریسک‌ها

| عیب | میتگیشن |
|-----|---------|
| **دو مکان برای toggle** | همگام‌سازی لازم است — اگر فقط در کاتالوگ خاموش کند و پیش‌نمایش را نبیند، گیج می‌شود → سوییچ کاتالوگ فقط وقتی در زنجیره است فعال باشد + تولتیپ راهنما |
| **اسکرول بیشتر** | تب + پیش‌نمایش = ارتفاع مودال بیشتر → مودال `max-height: 90vh; overflow:auto` فعلی کافی است؛ پیش‌نمایش `max-height: 220px` تا مودال منفجر نشود |
| **افزودن کُند برای پاورکاربر** | افزودن ۵ مدل نیاز به ۵ کلیک جدا (vs یک `select` + `Add` سریع) → دکمهٔ `[افزودن همهٔ پیشنهادی]` در هر تب (اختیاری V2) |
| **یادگیری اولیه** | کاربر قدیمی که به لیست واحد عادت کرده باید بفهمد ترتیب کجاست → بنر راهنمای یک‌بارمصرف `💡 ترتیب نهایی را پایین ببین` + هایلایت پیش‌نمایش در اولین باز شدن |
| **پیچیدگی پیاده‌سازی** | دو رندر (کاتالوگ + پیش‌نمایش) به‌جای یک `renderChain` → ولی منطق `storage` همان می‌ماند؛ فقط View لایه جدا می‌شود — هزینه قابل قبول |

## ۱۰. پیاده‌سازی (برای `ticket/xx-polish-tabs`)

**فایل‌های درگیر:**
- `index.html:118-149` → جایگزینی سکشن polish با مارکاپ تب + پیش‌نمایش
- `css/app.css:129-155` → کلاس‌های جدید: `.polish-tabs`, `.polish-tab`, `.polish-tab[aria-selected=true]`, `.polish-panel`, `.polish-catalog`, `.polish-preview`, `.dot-groq/.dot-or`, `.preview-item`
- `js/app.js:118-385` → دو تابع رندر: `renderPolishCatalog(tab)` + `renderPolishPreview()` به‌جای یک `renderChain(...,'polish')`; هندلر تب `switchPolishTab(provider)`; `persistChains()` بدون تغییر

**کلاس‌های پیشنهادی (وابسته به `css/app.css` موجود):**

**تست دستی (طبق AGENTS.md §3):**
1. فایل ۵ ثانیه فارسی ضبط کن → پالیش با زنجیرهٔ پیش‌فرض Groq بخورد.
2. تب OpenRouter → `openai/gpt-oss-20b:free` را `＋ افزودن` کن → پیش‌نمایش باید `③` شود.
3. در پیش‌نمایش `⋮⋮` را بکش به جایگاه `①` → ترتیب عوض شود، لاگ `polishChain` را چک کن.
4. `همهٔ Groq خاموش` → فقط Groqها `polish-off` شوند، OpenRouter روشن بماند.
5. با `Tab` و `ArrowLeft/Right` بین تب‌ها بچرخ، با `Enter` افزودن را بزن — صفحه‌خوان ترتیب را بخواند.

## ۱۱. تصمیم و گام بعدی

- **توصیه:** Alt C برای هم‌نگار مناسب است چون mental model کلیدها (سه سکشن جدا Groq/Gemini/OpenRouter) را بازتاب می‌دهد و درد «Add گیج» را ریشه‌ای حل می‌کند.
- **اگر تیم هزینه را زیاد دید:** نسخهٔ **C-lite** — فقط تب‌ها + پیش‌نمایش، بدون سوییچ تکراری در کاتالوگ (سوییچ فقط در پیش‌نمایش).
- **نیاز به تأیید:** رنگ نقطه‌ها (نارنجی/بنفش/آبی) با پالت `app.css:1` هماهنگ است؟ جایگزین: بج متنی پررنگ بدون نقطه اگر کنتراست کافی نبود.
